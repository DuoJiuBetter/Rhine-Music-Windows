# 播放队列与模型来源适配

工作分支：`feat/playback-queue-view`。回退基线：`8fa3083`，旧 Controls1 便携包与安装包保留。本次只生成本地预览，不公开发布。

## 用户行为

- 右上角新增队列入口，使用现有亚克力场景展示播放队列。没有创建第二个 ArchiveScene；继续使用现有模型池、遮挡计算、封面与材质预算。
- 歌单浏览、搜索结果模型、当前播放队列分别保留意义。临时队列的任何操作均不写回账号歌单；收藏仍通过原有“添加到歌单”流程。
- 队列条目增删与分页刷新保留正在打开的歌词/详情页、相机和抬起姿态，并保留封面驻留资源；后台本地索引更新不会覆盖队列或搜索模型视图。
- 搜索结果的“下一首播放”仅插队，不打断当前歌曲，也不强制跳转场景。后加入的“下一首”排在先加入的前面，用户可以在队列列表中调整。
- 立即播放搜索歌曲时保留已有来源与位置，插播完成后续播。尚未有播放来源时，搜索结果页建立新的来源。
- 队列工具条提供返回浏览、查看来源、定位当前和列表。列表支持播放指定条目、上移/下移未来曲目、移出队列；当前条目不能直接移除。列表先绘制 100 项，需要时按 100 项展开。
- 返回来源只切换浏览；主动浏览歌单或搜索结果时不会被自动播放拉走。队列内单次选择模型只浏览，再次点击突出模型进入详情并播放。方向键是否同步播放继续受已有设置控制。
- 从搜索结果模型再次点击突出项播放时，切到队列后继续打开该歌曲详情；用户在加载期间主动返回或改选来源时，不强制重新打开旧详情。
- 同一首歌允许多次临时入队，每次都有独立条目标识。歌曲 ID、音源路径、平台 ID 与封面 URL 不变，不向媒体接口发送队列条目标识。
- 顺序播放在临时歌曲结束后继续原来源下一首；随机模式优先完成手动安排，再恢复来源随机选择；单曲循环在临时插播结束后恢复原循环歌曲。已播放的临时歌曲不会自动进入原歌单下一轮循环。
- 队列为本次会话数据，重开软件后不恢复。临时待播上限 100 条；重访插播历史及续播信息有界保留，账号变化清空会话。
- 大歌单继续使用现有分页导航；列表标注“已载入”和“原歌单按需续载”，不为展示队列而一次获取整份大歌单。页面刷新保留当前临时歌曲、待播顺序和有限历史。

## 实现边界

`playback-queue.ts` 区分媒体标识和队列条目标识，合并分页刷新。`MusicPlayer` 保留原来源锚点、条目续播位置和本会话移除项，避免插入歌曲恰好属于原歌单时跳到错误位置。普通播放、无缝接续、暂停恢复和异步取消保留原输送流程。

`MusicQueueView` 只管理队列工具条与列表。三维入口仍使用 `playbackAlbums` / `setPlaybackAlbums` / `scene.refreshLibrary`。列表与工具条适配日/夜主题、减少动态效果和窄窗口；ResizeObserver 只观察宿主尺寸并在销毁时释放。

## 验证

- 类型检查与生产构建。
- 播放器、无缝接续、模型条目、歌单管理与一起听协议共 137 项 CPU 回归通过。
- 新用例覆盖重复插入、原来源锚点、与原歌单同名歌曲、自动结束、暂停队列编辑、上一首历史、移除/排序、分页刷新、容量边界及单曲循环回归。
- `scripts/check-playback-queue-ui.mjs` 运行生产 music-app、MusicPlayer、分页歌单和 DOM；只替换场景与媒体元素，显式禁用 GPU，拦截全部 API。
- 合成端到端场景：本地 B → 搜索 X → 原来源 C；立即搜索插播后接回原来源；模拟登录歌单 B → 临时 D → 临时 D → C；查看来源不打断播放；原歌单不变且没有平台写入。
- 覆盖列表上移/下移/移除、返回浏览、定位、设置关闭后工具条恢复、快捷键同步指定条目、浅/深主题，以及 800×560、800×1000、1024×768、1920×1080、2560×1440 的队列工具栏边界。
- 原有启动、设置、窗口按钮与帧时钟回归通过。
- `scripts/check-playback-queue-scene.mjs` 的 2 项 CPU 检查执行生产 `refreshLibrary` 方法，确认队列局部更新保留相机/摆放/弹簧对象、详情姿态与封面图集，且未加载场景仍为空操作。界面用例额外覆盖歌词页插入下一首不收起页面，以及媒体请求不携带队列条目标识。

没有访问真实账号或私人曲库，没有播放真实音频，没有执行真实 WebGL/GPU 性能捕获。本次不改原生宿主，打包复用 Controls1 已编译宿主；合成场景通过不等于已验证所有显卡上的模型视觉与帧率。
