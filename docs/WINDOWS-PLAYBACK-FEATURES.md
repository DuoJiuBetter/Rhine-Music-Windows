# Windows 播放功能：播放顺序、自定义快捷键、歌词切换动画

基线：`d3b0cf8`（Perf22 性能改动之后）。三个功能都以源码形式实现，不再是打在构建产物上的补丁；设置项都在 **设置 → 个性化**，偏好写入已有的 `rhine-music-preferences`。

## 一、播放顺序（顺序 / 循环 / 单曲循环 / 随机）

**位置**：顶栏播放控件左侧四个图标按钮（`data-playback-order`），激活态取主题强调色；窄窗口（≤1100px）隐藏以保住播放控件空间。

**实现**：`src/music-playback-order.ts` 拥有模式定义、纯函数策略与图标；`MusicPlayer` 新增状态字段 `playbackOrder` 与 `setPlaybackOrder()`，并把原先四处硬编码的 `queue[currentIndex + 1]` 全部改为走同一策略：

- 顺序：最后一首播完停止；
- 循环：播完回到第一首（单曲队列也保持重复）；
- 单曲循环：**曲终重复当前这首**，但用户按「下一首」仍然前进（与主流播放器一致）；
- 随机：队列被洗成一轮随机序（当前播放的曲子始终留在首位，一轮内不重复），此后按循环语义走完并回绕；退出随机时用 `restoreQueueOrder` 精确还原作者顺序，且**不会丢掉随机期间新增的曲目**（在线歌单可能在播放中续接队列）。

语义在 `next()`、`previous()`、浏览器 `ended` 回调、无缝播放的 `prepareSuccessor()`（含浏览器与原生两条路径）中一致，因此无缝模式与普通模式的切歌行为不会分叉。

## 二、自定义快捷键

**位置**：设置 → 个性化 → 「自定义快捷键」，12 项动作逐项绑定；底部「恢复默认（1 上一首 · 5 单曲循环）」「清空全部」，下方有状态提示行。

**默认绑定即需求原文**：`1` = 上一首，`5` = 单曲循环。

**实现**：`src/music-shortcuts.ts` 负责绑定表归一化、按键匹配与捕获状态机（纯函数）；应用侧只提供动作实现 `runMusicShortcut()`，设置界面与键盘处理共用同一张表：

- 点击按键框进入等待状态，按下即绑定；`Esc` 取消，`Backspace` / `Delete` 清除该项；
- **一个按键只属于一个动作**：绑定已被占用的键会解除原动作并在提示行说明；
- 空格、`Enter`、`Tab`、`Esc` 是界面保留按键，拒绝绑定并给出提示（避免与既有的播放/暂停、专辑打开、焦点循环、关闭浮层冲突）；
- 带 `Ctrl` / `Alt` / `Cmd` 的组合键不作绑定，不干扰浏览器与系统快捷键；
- 输入框、下拉框、可编辑区域内不触发；未绑定的按键完全不影响原有行为。

## 三、歌词切换动画

**位置**：设置 → 个性化 → 「歌词切换动画」，含**实时预览**（每 1.7 秒自行换句，不必去放歌）。

| 切换效果 | 行为 |
| --- | --- |
| 无动画 | 直接切换（恢复原行为） |
| 淡入淡出 | 透明度与颜色渐变（默认） |
| 上滑淡入 | 非当前句下沉 10px，成为当前句时上滑就位 |
| 缩放聚焦 | 非当前句缩到 95.5%，成为当前句时放大归位 |

速度：慢 520ms / 标准 320ms / 快 170ms。

**实现**：`src/music-lyric-motion.ts` 拥有选择、持久化形状与设置标记；效果本身写在 `src/music-song-view.css`，只过渡 `opacity / color / transform`（合成友好、**不动字号**，长歌词不会引发重排）。基础时长通过 `--lyric-motion-duration` 写入，再乘软件既有的 `--music-motion-scale`，因此"动效速度"设置照常生效；开启「减少动态效果」时一律不播放动画。

**未验证**：未在真实账号的在线歌单上跑完整的随机播放一轮（本地合成曲库已验证队列逻辑，纯函数层面覆盖洗牌与还原）；未在真实设备上做音频听感确认（切歌点、无缝衔接）；三个功能都没有实机截图归档。

## 与既有实现的关系

- 没有改动 `src/music-order.ts`（那是专辑**排序**）；播放顺序是新模块。
- 没有改动歌词解析、歌词渲染、设置分类与主题逻辑；动画只通过现有 `.lyric-line` 结构与 CSS 变量接入。
- 新增 npm 脚本 `check:shortcuts`，与 `check:glass`、`check:adaptive` 并列，便于持续验证。
