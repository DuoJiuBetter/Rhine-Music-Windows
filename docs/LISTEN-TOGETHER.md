# Together1 本地体验版 · 2026-10-16

独立分支 feat/play-next-and-listen-together，基于 1521ad6，旧的 Playlist1 与 Ripple3 包保留。未发布 GitHub，未重编译原生宿主。

## 入口和范围

- 搜索结果「下一首播放」将歌曲放入临时优先队列，最近一次选择优先，不打断当前进度；不修改云端歌单。顺序、随机、分页队列均尊重此优先队列。
- 在线歌曲详情提供「添加到歌单」，歌词进度条右上方提供无边框＋；选择当前平台自己创建的歌单。平台写入权限和限制沿用歌单整理。
- 网易云歌曲的「歌曲详情／歌词列表」旁新增「一起听」。可创建房间、复制官方邀请链接、粘贴官方链接加入；展示成员、共享队列数量、播放状态、文字聊天与历史。退出有确认窗口，收到平台退出确认才显示成功。
- 当前不自动读取联系人、不发送私信邀请、不伪造地理距离或平台未返回的资料；没有声称逐项复刻官方页面的全部功能。QQ／波点没有一起听入口。
- 波点曲目添加／移除采用已核实的 PyBodian 协议，仅限自己的歌单；新建、改名和整张删除仍不开放。

## 同步和资源约束

前端仅用本机同源 HTTP，保留 Host／Origin／JSON 校验。服务端复用锁定 NeteaseCloudMusicApi 4.32.0 的 Together 模块；房间状态约每 2 秒读取，参与后每 10 秒心跳。云信聊天与播放事件使用官方 node-nim 10.10.13；SDK 仅存在于可终止子进程，令牌通过 IPC 传入，避免原生 SDK 阻塞本机服务。无前端 WebSocket 连接。

远端状态应用期间不再广播，保留队列顺序，不把当前歌曲不断挪到首位。账号版本隔离、过期请求取消、聊天最多 200 条、曲目资料最多 100 条、共享队列最多 5000 首。写入不自动重试，聊天必须收到成功回调后才显示发送成功。历史与成员仅显示平台实际返回的资料。关闭 UI 不自动退出房间；主动退出使用确认后的平台结束接口。

## 核实来源

- 本地锁定 SDK 的 listentogether_status、room_create、accept、end、heatbeat、sync_playlist_get、sync_list_command、play_command，及官方邀请页 https://st.music.163.com/listen-together/share/。
- [Cove Resonance](https://github.com/yanceydaisy/cove-resonance) 的 client.ts、realtimeTransport.ts 和 nimTicketBootstrap.ts 用于核对聊天室授权、播放命令和原生 SDK 票据流程。MIT，版权 Yancey 2026；见 third-party/Cove-Resonance-LICENSE.txt。
- [node-nim 官方仓库](https://github.com/netease-im/node-nim) 和安装的类型声明用于核对原生回调。Windows SDK 回调房间 ID 可能为字符串，须规范化后比较，不能与数字严格比较后误判未连接。
- [PyBodian](https://github.com/MoeclubM/PyBodian) 的 bodian_toolkit.py，核实波点歌曲增删协议；沿用已有许可。

## 验证和未验收项

接口／播放器合成测试覆盖账号切换、房间创建／退出确认、邀请格式、队列、播放命令、聊天消息、错误不重试、波点签名 POST 及网易云歌曲端点。浏览器合成场景检查三个标签、＋入口、队列顺序、远端不回声、暂停后第一次恢复广播、草稿保留、HTML 转义、退出取消和确认、搜索下一首与主题。该场景不启动三维模型或实际音频。

本次合并运行 167 项接口／播放器／平台回归全部通过；Together、歌单整理、网络搜索、歌词滑动及总览交互检查通过，TypeScript 与生产构建通过。构建保留既有音频大包提示，没有引入新的三维渲染通道或重新跑 GPU 性能基准。

在维护者授权的保存账号上，实际验证创建仅有本人参与的临时房间、聊天授权与 SDK 入房成功、写入临时共享队列，以及暂停在 15000 ms 的播放命令回读；随后正常退出，退出已由平台确认。没有播放音频、邀请其他人、发送真实聊天或修改个人歌单。双人邀请加入、真实聊天收发与跨设备同步仍需两人验收。UI 合成测试通过不等同于这些项目已经真实通过。
