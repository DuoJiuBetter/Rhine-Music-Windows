# 歌单模型缺口修正

基线：a82e27e（BrowseRepeat1）。独立分支 fix/playlist-shell-navigation。

源码排查发现分页元数据位置与模型外壳存在性使用了不同判据，并修正播放列表附加后的列周期。未读取或公开真实账号、索引、录屏或个人封面。

## 源码问题

1. 歌单分页是每页 50 首，前端只在已取得资料的位置建立歌曲记录。`playlistFile` 对尚未取得资料的位置返回 -1；正常浏览的外壳可见性原来使用 `actualCell`，因此把这些已知存在的歌单位置当成不存在，直接隐藏模型。此前的 `playlistShellExists` 保护只在开场中启用。
2. 播放列表会增加一列，歌单映射周期随之增加。`navigatePlaylist` 原来仍使用歌单数量计算物理列，方向导航还直接把物理列加减一，可能进入播放列表列或另一首歌单的循环别名。

## 修改

- 正常浏览与开场都使用歌单已知位置判断外壳是否存在。详情页或封面尚未加载时仍保留玻璃板，封面继续由现有分页与有界图片调度器补全，不伪造歌曲图片或宣称其可播放。
- 歌单定位使用实际列周期。方向导航越过额外播放列表列，保持目标歌单和物理模型列一致，修正末列到首列及反向循环。
- 当前选中歌单的元数据窗口在可见区域前后各增加一页预取，按循环距离优先加载更近的页。相邻歌单仍使用原窗口；继续共享两个 HTTP 请求槽和 96 页缓存，不对所有大型歌单全量下载。
- 保留现有 9×48 显示池、可见部分裁剪、封面并发／缓存预算；不一次加载整个大型歌单。

遵循维护者此前要求，不执行类型检查、测试、真实界面／GPU／音频／账号验证。仅打包前端，复用 Windows 宿主，runtimeChecked=false。网络导致的图片下载失败或延迟仍可能出现无封面玻璃板，不属于完整实机验收。
