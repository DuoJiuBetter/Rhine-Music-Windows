# 中间窗口按钮行为修正

版本：0.4.1-preview-windowmode-1。上一版为 layout-1；未公开发布。

## 正确的操作逻辑

设置 → 画面显示设置 → 窗口与全屏，仅提供“最大化模式”和“全屏模式”。这两项是右上角中间按钮的行为偏好，选择设置本身不调整窗口大小。

- 最大化模式：普通窗口点击中间按钮，按工作区最大化，保留任务栏。
- 全屏模式：普通窗口点击中间按钮，进入原生全屏，覆盖任务栏。
- 已展开时再次点击中间按钮，均还原普通窗口；三个窗口控件在两种模式下都保留。
- 顶部双击沿用相同偏好，单击拖动仍由原生拖拽处理。
- 偏好随现有设置保存，重新打开软件后保留。无效或旧版缺失数据默认最大化模式。
- F11 仍可直接切换全屏，Esc 退出全屏，不改写中间按钮的偏好。

## 任务栏仍显示的原因

只读检查旧版运行窗口时，观察到外框为 2560×1600、内容区为 2560×1528，内容区与系统工作区恰好一致，而且 Windows 的最大化标志仍为 true。

锁定依赖 tao 0.37.1 的 Windows `WM_NCCALCSIZE` 实现，在无边框窗口仍为 `IsZoomed` 时使用 `rcWork` 作为内容区，即使内部 fullscreen 状态已经为 true。因此外框虽然覆盖显示器，内容仍可能避开任务栏。

新的原生全屏入口先解除最大化，再进入全屏并激活窗口，让内容区使用整个显示器。Tao 原有的任务栏全屏标记逻辑保留；没有隐藏 Explorer、改系统任务栏设置或将窗口永久置顶。

控件消失则来自 layout-1 的 CSS 主动隐藏规则，本版删除该规则。

## 检查与边界

- `npm run check:window-controls`：模式规范化、展开/还原决策；生产 Rust 全屏函数提取后的 6 个 CPU 模拟测试，覆盖解除最大化顺序、普通窗口、已全屏幂等处理及各阶段错误传播；实际设置 DOM + 合成原生接口验证偏好保存、选择不调整窗口、按钮/顶部双击、控件可见、F11/Esc、无 resize 事件及部分失败后仍可还原。
- 启动生命周期检查、类型检查、生产构建通过。
- 原生宿主复用锁定依赖，单任务离线 release 编译通过；没有清理编译缓存或执行 GPU 压力测试。
- 旧窗口仅做尺寸和状态读取，未关闭、激活、移动或切换该窗口。新宿主未在本轮实际打开窗口，最终全屏内容区及任务栏遮挡行为尚需新版本的实机体验确认，不能以模拟测试代替。
- 保留 layout-1 及更早包，源码在独立分支 `fix/maximize-button-mode`。
