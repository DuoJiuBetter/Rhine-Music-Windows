# Rhine Music · Windows 开发预览 0.1.0 · Perf21

基于 RonaldDeng/Rhine-Music-Demo V0.4.1 的独立 Windows 移植工作区。保留上游视觉、资源及署名。当前版本是社区开发预览，核显性能目标尚未完成完整实机验收。公开包的许可、隐私和第三方平台边界见 README.md、PLATFORM-NOTICE.md 与 PRIVACY.md。

## 运行

解压后双击 `Rhine Music.exe`，保留旁边的整个 `runtime` 文件夹。
支持 Windows x64，使用 Microsoft Edge WebView2 Runtime。已内置 Node.js，无需安装 npm、Rust 或 Node.js。首个 Public 公开包不捆绑 FFmpeg/ffprobe；需要额外解码格式或相关无缝播放路线时，请自行安装并通过 PATH 或 FFMPEG_PATH / FFPROBE_PATH 指定。此前本地测试包包含的可选 FFmpeg 与公开包不同。WebView2 使用系统运行时；未安装时请安装微软的 Evergreen WebView2 Runtime。当前 EXE 未签名。

加载完成后直接进入三维谱面阵列。没有本地歌曲、也没有当前在线播放队列时，显示空白玻璃谱面模型，不再展示添加音乐的引导页，也不自动填入演示封面。未登录仍可播放本地歌曲和搜索网易云试听。

在顶部“设置”中点击“管理音乐库”，然后点击“选择文件夹”，确认列表后点击扫描。“暖昼 / 深夜”主题也在设置中切换。程序不会预先扫描私人音乐目录。音乐文件与标签只读，曲库索引、封面、PCM 缓存保存于 `%LOCALAPPDATA%\local.rhine.music.windows\music-data`。界面偏好保存在 WebView2 用户数据中；窗口位置由桌面程序保存。

F11 切换最大化与还原，铺满桌面可用区域并保留任务栏。专辑详情中的 Escape 返回专辑架，总览中的 Escape 返回近景，专辑架中的 Escape 还原窗口。右上角透明窗口按钮支持最小化、最大化、还原和关闭，与场景背景融为一体，不额外占用标题栏空间。窗口顶部空白区域可拖动，双击最大化或还原；右侧窗口按钮仍可正常点击。旧预览保存的全屏状态不再恢复。第二次启动唤回已有窗口。最小化暂停三维绘制，歌曲继续播放；关闭退出程序并停止其本地服务。

Perf8 默认请求高性能显卡：NVIDIA Optimus 宿主提示与 WebView2 GPU 偏好共同作用。有 MX550 等可用独显时优先请求独显，仅有核显时使用可用核显；Windows 图形设置、驱动和外部 WebView2 参数仍可能覆盖偏好。设置显示实际渲染显卡，不能将请求标记当作已切换成功。此版本重新编译了 EXE；只替换旧版本的网页资源不能启用新的宿主提示。

设置新增“画质选择 → 自动适配 / 手动设置”。自动适配读取实际 WebGL 显卡、窗口物理像素、可用的 CPU / 内存提示，保守选择核显、MX 入门独显或增强独显预设；型号识别是启发式配置，不是实时性能测量。主画面像素上限分别为 144 / 207 / 369 万，保留可见完整玻璃、区域遮挡及独立清晰封面。首次使用及旧版的精确核显默认预设进入自动模式；既有原始、高、自定义与明确的手动模式保留，任何手动调整都会退出自动模式。自动模式在每次启动时按本机重新选择，窗口尺寸变化仍受对应像素上限限制。

封面在切换前准备当前、邻近歌曲 / 歌单与可见阵列，前三张详细候选保留 1024px，其余保留 256px 缩略图。解码缓存上限 48 MiB / 192 张，预加载待解码队列上限 32；后台最多两个解码，选中歌曲可使用第三个通道。预加载只准备 CPU 图像，画布绘制和 GPU 局部上传继续按帧预算执行。柱子歌名提前加载可见区及前后相邻页，已有歌名立即显示；冷请求期间保留歌曲编号，未返回的网络数据无法保证立即可见。没有整库或整歌单无限预载。

当前交付 Perf21。诊断应显示 `0.4.1-perf21`，下载包请以本仓库 Release 中的 Public 包为准；此前本地预览记录只作历史说明。最新行为依据见 [Perf21 说明](docs/WINDOWS-PERF21.md)。本轮未运行播放器、GPU、账号或音频回归，具体效果待实机确认。

设置改为覆盖整个窗口的分类界面：本地歌单设置、个性化、画面显示设置、开发者设置和反馈。网易云 API 使用独立 IPv4 连接池，保留既有 TLS 校验、超时、队列和三次重试，不更改系统网络或其他平台。设置 → 开发者设置中的“显示详细报错”默认关闭，选择会保存；打开后可查看 / 复制调试码和 JSON。关闭浮层不停止错误采集。设置 → 反馈可填写问题并打开寄往 2228396737@qq.com 的邮件草稿，自动带入版本、画质、窗口和最近错误摘要；完整诊断可复制或保存，邮件由用户确认发送。最多保留本次运行最近 20 条，增加原始 cause / AggregateError 深层链、errno、syscall、安全消息和调用位置，以及网易云请求和 TLS / 连接阶段时间线。连接池事件明确标为同域时间窗口辅助证据。凭据、私人路径、请求参数、原始响应和音源 URL 不导出；退出清除。沿用三次重试；本版针对测试中 IPv6 断连采用 IPv4，热点下实效仍需用户复测。左上角文字保持纯展示，图标恢复圆角白底并保留放大的黑色标志，宿主重新编译。

Perf19 在线音源请求 / 音频加载遇到临时错误时最多自动重试 3 次，间隔 0.6 / 1.4 / 2.8 秒，每次重新获取地址；自动下一首同样适用。保持当前歌曲与进度，暂停 / 停止 / 切歌 / 换账号会取消等待。明确登录、权限和请求无效错误直接显示；用尽次数后显示失败，避免持续请求。QQ 曲库网络失败不再误标为登录请求失败。我的歌单标题与列表总宽缩至 280px，名称 240px / 右侧箭头 40px，列表最高 260px；箭头固定占位，仅悬停或键盘焦点时显现，触摸设备常驻，不再改变卡片宽度。抽屉与歌曲定位保留。

Perf17 修正波点自建 / 收藏歌单空响应被当成格式错误：空来源不再阻断其他歌单和我喜欢；未知非空结构仍报告错误，注明来源并只展示安全字段类型。null / 缺失总量不再被强制变成零，保留歌曲数量与分页。沿用本机账号，不必主动退出重登。没有访问真实账号，实际结果仍需新包确认。

Perf16 增加歌单名称卡片展开为列表、以及返回时的连续形变与内容淡入。支持暖昼 / 深夜、动效速度、减少动态效果和快速打断；不增加三维渲染通道。加入波点音乐 App 扫码入口，登录后切换对应搜索、个人歌单、三维阵列、封面、资料、歌词与音源，账号单独加密保存。第三方协议的真实可用性及动画观感待用户在新包确认。

Perf15 调整详情背景的景深重建与封面清晰通道，避免远处薄卡片边缘重新变成锐利条纹；抽出的歌曲封面保持清晰。歌词只在进入页面时对初始可见部分揭示，之后切句或滚动直接显示。播放 / 停止改为无边框控件，上一首 / 下一首采用独立箭头和中文，进度圆点只在悬停、拖动或键盘焦点时显示。具体视觉效果待实机确认。

Perf14 修正 QQ“我喜欢”被缺失的可选账号字段阻断，以及播放固定请求错误音频文件的问题。播放先由平台选择可用资源，未返回地址时最多追加一次实际文件 ID 的普通 MP3 / AAC 请求；平台若返回可播放片段则按其地址播放。无法保证 QQ 网页接口为所有受限歌曲提供试听，未返回地址不直接归因于会员。宿主沿用 Perf13 的圆角图标和显卡偏好 EXE，网页与服务代码重新构建打包。

音频经本机 FFmpeg 解码及 WebView2 输出到 Windows 默认设备。DSF/DFF 转为 PCM，源文件不改写。当前不包含 Windows WASAPI 独占、ASIO 或 bit-perfect 输出。系统音量和默认输出设备仍由 Windows 控制。

## 网络搜索与平台账号

打开“搜索”默认进入“网络搜索”，使用当前登录平台的曲库，输入歌曲、歌手或专辑名称并按 Enter 或点击搜索。搜索框、账号区和结果链接标明平台；未登录首次默认网易云。结果支持分页，点击歌曲播放平台当前提供的音源，本地音乐搜索仍可切换使用。

点击主界面右上角“登录”，选择网易云音乐 / QQ 音乐 / 波点音乐。网易云和波点分别使用对应手机 App 扫码确认，QQ 音乐可选 QQ 或微信扫码。登录成功或核对已保存账号后切换当前平台，同时切换搜索、我的歌单、歌曲资料、歌词与播放。各平台会话分别保留；选中已登录的平台即可切换，当前平台退出后恢复本地曲库。支持二维码过期和刷新；扫码页取消按钮已移除，关闭面板或切换扫码方式会取消旧挑战，最小化暂停轮询。

Windows 使用当前用户的 DPAPI 分平台加密保存登录信息，文件位于上述本机数据目录的 `netease-session.dpapi`、`qq-session.dpapi`、`bodian-session.dpapi`。登录令牌不返回网页、不进入 localStorage 或日志、不随运行包分发。重新启动恢复并核对上次平台，其他平台在选中时核对；退出只清除对应平台。加密保存失败会提示仅保持本次内存登录，非 Windows 不保存凭据。

播放范围取决于当前平台返回的地址和账号权限，可能提供完整歌曲、试听片段或不提供音源；搜索到歌曲不代表可以完整播放。登录后读取对应账号创建和收藏的歌单。三个平台均为第三方协议适配，非官方合作 SDK；本轮只检查代码和构建，没有进行真实账号、搜索、私人歌单、歌词或会员音源测试。接口、风控、地区和内容权限变化可能导致失败，实际可用性须实机确认。

请求由现有本地服务按需发起，不增加常驻后台服务。搜索结果只在内存短时缓存，最多 100 项，账号变化后失效。歌曲按需流式播放，每次开始播放重新获取音源地址。在线播放沿用系统共享输出，暂不保证在线歌曲无缝衔接。

## 播放队列与三维专辑

登录后，并排的每一排谱面对应当前平台账号的一个歌单，同一歌单里的歌曲沿该排向前后延伸，按平台歌单顺序排列。卡片使用歌曲所属专辑的封面，焦点显示歌曲与歌单名称。左右方向键循环切换歌单，上下方向键或滚轮循环浏览同一歌单的歌曲，空格播放选中的歌曲。末尾继续前进会接到开头，开头继续后退会接到末尾；模型沿原方向移动，重复利用原有显示池。每个歌单按自己的歌曲数量循环，切换到短歌单时取对应的循环位置；空歌单保持空白谱面。

点击未选中的卡片先选中，再次点击已经突出的选中模型，会进入歌曲详情并开始播放。我的歌单详情中显示“返回歌单”，开始 / 停止共用一个按钮；右侧为中文上一首 / 下一首，播放后显示歌词，下方仅保留进度条和时间，播放 / 暂停使用顶部控件。播放加载完成后可拖动进度条，暂停时拖动仍保持暂停；停止后进度归零，重新开始前进度条不可拖动。本地专辑详情继续使用原曲目列表。循环浏览不改变播放器原有的自动切歌策略。

顶部“我的歌单”可直接选歌单或刷新。浏览其他歌单不会打断当前播放；暂停和停止后保留歌单阵列，退出账号后恢复本地曲库。歌单歌曲按每页 50 首读取，最多两项并发、缓存 96 页元数据，随焦点加载邻近区域，不在登录时一次获取所有歌曲和封面。播放时按需补充同一歌单的前后曲目，保留歌单顺序。歌单元数据仅在内存缓存，退出或切换账号清除。

上下箭头之间显示当前歌单的歌曲柱，每首歌对应一根柱子，数量依据歌单总数，不受当前已读取页数限制。当前歌曲的柱子突出；鼠标停留或键盘聚焦时高亮该柱，在其上方显示对应歌名。长歌单在固定宽度区域内横向滚动，选中歌曲会移入可见区域；滚轮循环切换歌曲，点击柱子直接定位，三维模型同步选择，浏览不会自动播放。尚未读取的歌名按需获取，读取失败显示明确提示，不用歌单名称代替歌曲名。

## 当前性能工作

Perf7 是完整玻璃的遮挡面积优化预览，目录 `release/Rhine-Music-Windows-Perf7`，ZIP `Rhine-Music-Windows-0.1.0-perf7-preview-x64.zip`。每帧用原模型正面平坦三角形的精确子集预绘制主画面深度，然后让硬件深度测试跳过会被前景覆盖的玻璃像素；保留圆角、孔洞、完整玻璃着色及所有其他通道的几何。不把玻璃当作透射背景中的不透明挡板，仅适用于本项目最终颜色不混合、写深度的物理外壳。透射背景、阴影、AO、景深、清晰封面、SMAA 和尺寸预算沿用 Perf6。

设置 →“玻璃遮挡优化”默认开启，本次会话可即时关闭对照或打开三类调试。红色表示当前姿态深处遮挡，黄色表示边界 / 动效不确定，绿色表示当前露出核心；重叠层按比例混色。动效中统计全部按不确定处理，实际深度仍每帧重建，模型没有永久删减。调试 / 面积采样依赖 float render/blend 扩展，缺少支持时优化继续运行，统计显示 unavailable。面积是低分辨率投影层样本估计，不是精确像素，也不是性能提升倍数。正常模式每 256 帧采样一次、最多一项异步回读，调试有额外开销；测试 FPS 应使用开启 / 关闭两种普通模式。关闭旧版后启动新包，诊断显示 `0.4.1-perf7`，`optimization.glassVisibility.active` 应为 true，并有 `glassVisibilityDepth` / 主场景 GPU 耗时。新增深度通道也有成本，实际帧率与视觉待实机；Perf6 保留为回退基线。

Perf6 是“可见卡片全部完整玻璃”对照预览，独立目录 `release/Rhine-Music-Windows-Perf6`，ZIP `Rhine-Music-Windows-0.1.0-perf6-preview-x64.zip`。取消 12 张完整玻璃上限及远景 Lambert 近似，所有与镜头保守视锥相交的卡片使用原物理玻璃；保留视野外裁剪、独立阴影范围、简化 / 限频阴影、封面帧预算以及 Perf5 的 SMAA、原生清晰封面和后处理尺寸。画质精细设置的“可见完整玻璃”对应原 `arrayBudget: 1`，已有偏好无需重置。对照时选“核显适配”，关闭旧版后启动新包，诊断应显示 `0.4.1-perf6`、`materialPolicy: all-visible-physical`、`nearGlass` 等于 `visible`、`farGlass: 0`、`nearLimit: null`。此前同类画面约 211 张可见卡片，并非只有焦点附近几张；GPU 成本可能明显增加，实际观感 / 帧率待实机。Perf5 包与源码检查点保留，可随时回退。

Perf5 是清晰封面 / 抗锯齿预览，独立目录 `release/Rhine-Music-Windows-Perf5`，ZIP `Rhine-Music-Windows-0.1.0-perf5-preview-x64.zip`。核显预设保留 Perf4 的模型像素、玻璃分级、阴影、AO 和景深预算，并默认开启 SMAA。封面在后处理后单独以屏幕分辨率绘制，跳过景深与玻璃透射模糊；共享深度判断遮挡并允许纸面与自身薄盖板的间隙，沿用原印刷光照和输出曝光。背景封面保留 256px 图集、选中封面 1024px；清晰度仍受图片源分辨率及投影视角限制。屏幕原生封面层增加 GPU 工作，实际清晰度、边缘和帧率待实机验收。关闭旧版后启动新版，复制诊断应显示 `0.4.1-perf5`、`antialias: smaa` 和 `clearCovers` / `nativeClearCovers`。

Perf4 是本轮核显组合预览：独立目录 `release/Rhine-Music-Windows-Perf4`，ZIP `Rhine-Music-Windows-0.1.0-perf4-preview-x64.zip`。核显预设自动启用主画面 DPR 上限 1 / 最多 1.44 MP、阵列最多 12 张完整玻璃、互斥近远绘制、Lambert 远处玻璃及反射近似、简化且限频更新的阴影、25% 透射尺寸、8 采样 AO、半分辨率 13 采样景深以及 128px 背景封面图集。选中卡片材质、选中封面和交互动画保留；UI 文字继续按系统缩放。旧版精确的核显预设自动迁移，自定义 / 原始画质保留；需要完整组合时明确选择“核显适配”。诊断标记 `0.4.1-perf4` 并报告各渲染阶段 GPU 耗时。

这版降低三维渲染分辨率，远处玻璃、软阴影及景深采用近似；视觉细节可能不同，不保证逐像素相同。仅进行代码检查、构建和包完整性校验，没有启动播放器或测量新帧率。先完整退出旧版再启动新 EXE。Perf3 原目录和 ZIP 保留，回退时关闭新版并打开旧包，再选择旧版核显预设以恢复其参数。

- Perf2 桌面默认使用“核显适配”，保留完整主画面、玻璃材质、光照及动效，降低透射、AO 和景深的内部分辨率。原始画质保留供对照，自定义画质保留。
- AO 的完整法线 / 深度与小尺寸遮蔽计算分离，景深复用完整深度；焦点处保持主画面清晰度。关闭 AO 时使用独立深度回退。
- 相同实例变换共享 GPU 缓冲，避免重复计算和上传。
- 交互和过渡以 60 FPS 为调度上限，静置保留 30 FPS 呼吸动画，最小化停止场景帧循环。
- 支持异步 GPU 计时；设备不支持计时扩展时明确报告 unavailable。

目标是现代集成显卡在 1080p 原始视觉下流畅交互。当前开发机为 i5-13400F / RTX 4070 SUPER，没有可用于验收的集成显卡。已有性能记录不代表 UHD、Iris Xe、Radeon 集显成绩，也不代表 60 FPS 已达标。详见 `docs/WINDOWS-VALIDATION.md`。

## 开发

Perf3 的独立可携带目录是 `release/Rhine-Music-Windows-Perf3`。核显适配继续启用 Perf2 的后处理预算，并新增距离玻璃分级、可见实例提交、独立阴影范围和切换期间的封面帧预算；选中卡片保留完整材质。画质精细设置中的“阵列渲染”可切回“完整材质”。首次升级仅为旧偏好补齐该控制，原始画质仍走完整路径。诊断记录近远 / 可见 / 阴影实例数及准备 / 上传预算。旧 Perf2 包、源码检查点和完整 Git 备份保留，方法见性能项目管理文档；关闭新版再打开旧版，对照时明确选择各自画质。此包只有代码检查与构建验收，实际视觉和帧率待实机测试。

Windows x64 环境需要 Node.js >=22.12、Rust stable、MSVC Build Tools 和 WebView2。

`release/Rhine-Music-Windows` 是可携带目录，含 SHA256SUMS.txt。打包脚本会重新创建项目内的 staging/release 目录，不会修改音乐目录。`desktop-binaries` 可放入配套 FFmpeg/ffprobe 与其许可；不存在时程序只探测系统 PATH，不保证所有格式可解码。`third-party/NODE-LICENSE.txt` 对应本次内置 Node.js 版本，升级运行时须同步许可。

本次性能优化独立放在 `release/Rhine-Music-Windows-Perf1`。Bars 版本保留为回退基线；先关闭当前版本再启动另一目录中的程序，否则单实例机制会唤回旧窗口。旧包运行时，打包脚本会在删除文件之前拒绝覆盖；可通过 `RHINE_PACKAGE_NAME=Rhine-Music-Windows-Perf1` 选择单独输出目录。本轮沿用用户的验证要求，仅完成静态代码检查与编译，未执行运行时、交互或帧率验收，不能视为核显性能达标。源码检查点、独立优化提交与回退方法见 `docs/WINDOWS-PERFORMANCE-PROJECT.md`。

Perf2 使用独立的 `release/Rhine-Music-Windows-Perf2` 目录和 ZIP；优化分支为 `perf/windows-integrated-gpu`。默认“核显适配”保持主画面 100%、原有景深强度及玻璃材质，透射 / AO / 景深内部宽高各 50%，AO 16 采样、阴影 1024。首次升级只迁移旧默认，保留自定义；之后手动选择“原始”会被记住。新旧包可能共用界面偏好，回退旧包时明确选“原始”。设置中的“复制性能诊断”包含实际渲染显卡、绘制尺寸和可用的 GPU 计时，不包含曲名、路径或账号凭据。本轮仅静态检查与编译，实际画质与帧率待用户核显实测。

默认服务仅监听 127.0.0.1:5175；端口占用则选择空闲端口，不连接其他进程的服务。由于浏览器偏好按 origin 隔离，端口回退时界面偏好可能使用另一份存储。扫描索引不受此影响。

上游 macOS 启动器及 CoreAudio 源码保留，Windows 默认入口为 EXE。完整发行回归在 Windows 明确跳过 macOS 专属设备与 Finder 启动器测试；APE 实际样本未提供时跳过该样本测试。
